# useActionState + useOptimistic: Modern Forms in React 19

I built a login form last week. In React 18, it took 47 lines of useState, useEffect, and manual validation. In React 19, it took 12 lines. The new useActionState hook handled the submission, the pending state, the error message, and the success redirect. I deleted three custom hooks and a utility function I thought I would need forever.

React 19 does not just add features. It removes complexity from the patterns you use every day. Forms are the biggest win. This guide shows you exactly how to build modern forms without the useState spaghetti you are used to.

## Key Takeaways

- **useActionState replaces useState for form submissions.** It gives you state, pending status, and error handling in one hook.
- **useOptimistic updates the UI before the server responds.** The user sees instant feedback. If the server fails, it rolls back automatically.
- **Server Actions let you submit forms without useEffect or fetch calls.** The form action attribute points directly to an async function.
- **Progressive enhancement works out of the box.** The form submits without JavaScript. React enhances it when the script loads.
- **Error handling is declarative.** No try-catch in your component. Errors are part of the returned state.

<Callout type="warning" title="The mental shift">
In React 18, you controlled everything with useState. In React 19, you declare what should happen and React manages the lifecycle. This feels like less control at first. It is actually less bugs.
</Callout>

## 1. The old way: why useState forms die

Here is the form pattern every React developer knows. It works. It is also exhausting.

```jsx
// React 18: The form pattern we all wrote
function LoginForm() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [error, setError] = useState(null);
  const [success, setSuccess] = useState(false);

  const handleSubmit = async (e) => {
    e.preventDefault();
    setIsSubmitting(true);
    setError(null);
    setSuccess(false);

    try {
      const res = await fetch('/api/login', {
        method: 'POST',
        body: JSON.stringify({ email, password }),
        headers: { 'Content-Type': 'application/json' }
      });

      if (!res.ok) {
        const data = await res.json();
        throw new Error(data.message || 'Login failed');
      }

      setSuccess(true);
      setEmail('');
      setPassword('');
    } catch (err) {
      setError(err.message);
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <input 
        type="email" 
        value={email} 
        onChange={e => setEmail(e.target.value)} 
        required 
      />
      <input 
        type="password" 
        value={password} 
        onChange={e => setPassword(e.target.value)} 
        required 
      />
      <button disabled={isSubmitting}>
        {isSubmitting ? 'Logging in...' : 'Login'}
      </button>
      {error && <p className="error">{error}</p>}
      {success && <p className="success">Welcome back!</p>}
    </form>
  );
}
```

**The problems:**
- Seven state variables for one form
- Manual event prevention
- Manual error clearing
- Manual success reset
- No built-in pending state for the button
- No progressive enhancement (JavaScript dies, form dies)

I have written this pattern 50 times. I made a typo in setIsSubmitting at least 10 of those times.
<Callout type="info" title="The boilerplate tax">
The average login form in React 18 requires 40-60 lines of state management. The actual logic (send email and password to API) is 6 lines. We were writing infrastructure, not features.
</Callout>

## 2. useActionState: forms in one hook

React 19 introduces useActionState. It is designed for exactly this pattern.

```jsx
// React 19: The same form, 60% less code
'use client';

import { useActionState } from 'react';
import { login } from './actions';

export default function LoginForm() {
  const [state, submitAction, isPending] = useActionState(
    async (prevState, formData) => {
      const email = formData.get('email');
      const password = formData.get('password');
      
      try {
        const result = await login(email, password);
        return { success: true, message: 'Welcome back!' };
      } catch (err) {
        return { error: err.message };
      }
    },
    null // Initial state
  );

  return (
    <form action={submitAction}>
      <input type="email" name="email" required />
      <input type="password" name="password" required />
      <button disabled={isPending}>
        {isPending ? 'Logging in...' : 'Login'}
      </button>
      {state?.error && <p className="error">{state.error}</p>}
      {state?.success && <p className="success">{state.message}</p>}
    </form>
  );
}
```

**What changed:**
- No useState for form fields
- No onChange handlers
- No e.preventDefault()
- No manual isSubmitting toggle
- The form uses the native action attribute
- Error and success are part of the returned state object
<Callout type="tip" title="Name attributes are required">
Notice the name="email" and name="password". Without these, formData.get() returns null. The browser handles the input values now, not React state.
</Callout>

## 3. Server Actions: submit without fetch

The real power comes when you move the action to the server. In Next.js 16, you can define a Server Action in a separate file.

```jsx
// app/actions.js
'use server';

export async function login(prevState, formData) {
  const email = formData.get('email');
  const password = formData.get('password');
  
  // Validate on the server
  if (!email.includes('@')) {
    return { error: 'Invalid email address' };
  }
  
  if (password.length < 6) {
    return { error: 'Password must be at least 6 characters' };
  }
  
  // Call your Spring Boot API
  const res = await fetch('http://localhost:8080/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password })
  });
  
  if (!res.ok) {
    const error = await res.json();
    return { error: error.message || 'Invalid credentials' };
  }
  
  const user = await res.json();
  
  // Set session cookie
  cookies().set('session', user.token, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    maxAge: 60 * 60 * 24 * 7 // 7 days
  });
  
  return { success: true, message: 'Welcome back!' };
}
```

Then your form becomes even simpler:

```jsx
// app/login/page.jsx
import { useActionState } from 'react';
import { login } from './actions';

export default function LoginPage() {
  const [state, submitAction, isPending] = useActionState(login, null);

  return (
    <form action={submitAction}>
      <input type="email" name="email" required placeholder="Email" />
      <input type="password" name="password" required placeholder="Password" />
      <button disabled={isPending}>
        {isPending ? 'Logging in...' : 'Login'}
      </button>
      {state?.error && <p className="error">{state.error}</p>}
      {state?.success && <p className="success">{state.message}</p>}
    </form>
  );
}
```

**The Server Action handles:**
- Validation
- API call to Spring Boot
- Cookie management
- Error formatting

**Your component handles:**
- Rendering the form
- Showing the button state
- Displaying the result

This is the separation of concerns we were promised in 2015.
<Callout type="warning" title="Server Actions need a framework">
useActionState works in any React 19 app. Server Actions require a framework that supports them, like Next.js 16 or Remix. If you use Vite + React without a framework, keep the client-side action pattern from section 2.
</Callout>

## 4. useOptimistic: instant UI with rollback

Here is the scenario. A user clicks "Add to Cart." In React 18, you have two choices:

- **Option A:** Wait for the server response. The user stares at a spinner. Feels slow.
- **Option B:** Update the cart immediately. If the server fails, you manually undo the change. Complex and buggy.

React 19 introduces useOptimistic. It gives you Option B without the complexity.

```jsx
// components/AddToCart.jsx
'use client';

import { useOptimistic, useState } from 'react';
import { addToCart } from './actions';

export default function CartButton({ productId, initialCount }) {
  const [cartCount, setCartCount] = useState(initialCount);
  
  // optimisticCount shows the updated value immediately
  // If the server fails, it automatically reverts to cartCount
  const [optimisticCount, addOptimisticCount] = useOptimistic(
    cartCount,
    (state, newItem) => state + 1
  );

  async function handleAdd() {
    // Update UI immediately
    addOptimisticCount(productId);
    
    try {
      // Server request happens in background
      await addToCart(productId);
      // Confirm the update
      setCartCount(c => c + 1);
    } catch (err) {
      // UI automatically reverts to cartCount
      // No manual rollback needed
      console.error('Failed to add:', err);
    }
  }

  return (
    <button onClick={handleAdd}>
      Add to Cart ({optimisticCount})
    </button>
  );
}
```

**How it works:**
1. User clicks button
2. addOptimisticCount fires. UI shows optimisticCount (cartCount + 1) immediately.
3. Server request happens in the background.
4. If server succeeds, setCartCount confirms the state.
5. If server fails, optimisticCount automatically reverts to cartCount.

No manual rollback. No temporary state. No "undo" logic.
<Callout type="info" title="The magic of useOptimistic">
The hook knows the difference between "confirmed state" (cartCount) and "optimistic state" (optimisticCount). When you call setCartCount, that becomes the new confirmed state. If you do not call it, the UI snaps back to the last confirmed state on the next render.
</Callout>

## 5. The complete pattern: form + optimistic update

Here is a real-world example. A comment form on a blog post.

```jsx
// components/CommentForm.jsx
'use client';

import { useActionState, useOptimistic } from 'react';
import { addComment } from './actions';

export default function CommentSection({ postId, initialComments }) {
  const [comments, setComments] = useState(initialComments);
  
  // Optimistic comments: shows new comment immediately
  const [optimisticComments, addOptimisticComment] = useOptimistic(
    comments,
    (state, newComment) => [...state, { ...newComment, id: 'temp-' + Date.now() }]
  );

  const [state, submitAction, isPending] = useActionState(
    async (prevState, formData) => {
      const content = formData.get('content');
      const author = formData.get('author');
      
      const tempComment = { content, author, createdAt: new Date().toISOString() };
      
      // Show comment immediately
      addOptimisticComment(tempComment);
      
      try {
        const saved = await addComment(postId, content, author);
        // Confirm with real ID from server
        setComments(prev => [...prev, saved]);
        return { success: true };
      } catch (err) {
        return { error: err.message };
      }
    },
    null
  );

  return (
    <div>
      <form action={submitAction}>
        <input name="author" placeholder="Your name" required />
        <textarea name="content" placeholder="Your comment" required />
        <button disabled={isPending}>
          {isPending ? 'Posting...' : 'Post Comment'}
        </button>
        {state?.error && <p className="error">{state.error}</p>}
      </form>

      <div className="comments">
        {optimisticComments.map(comment => (
          <div key={comment.id} className={comment.id.startsWith('temp-') ? 'pending' : ''}>
            <strong>{comment.author}</strong>
            <p>{comment.content}</p>
          </div>
        ))}
      </div>
    </div>
  );
}
```

**What the user sees:**
1. Types comment, clicks Post
2. Comment appears immediately in the list (with a "pending" style)
3. Button shows "Posting..."
4. If server succeeds, pending style disappears, real ID replaces temp ID
5. If server fails, comment disappears, error message appears

This pattern used to require 80 lines of manual state juggling. Now it is 30 lines with two hooks.
6. Error handling and retries
What happens when the server is down? Or the user's data runs out mid-submission?

useActionState gives you error state declaratively. But retries still need logic.

```jsx
function LoginForm() {
  const [state, submitAction, isPending] = useActionState(login, null);
  const [attempts, setAttempts] = useState(0);

  // Auto-retry on network errors (up to 3 times)
  const handleSubmit = async (formData) => {
    try {
      await submitAction(formData);
      setAttempts(0);
    } catch (err) {
      if (err.message.includes('network') && attempts < 3) {
        setAttempts(a => a + 1);
        setTimeout(() => handleSubmit(formData), 2000);
      }
    }
  };

  return (
    <form action={handleSubmit}>
      <input name="email" type="email" required />
      <input name="password" type="password" required />
      <button disabled={isPending}>
        {isPending ? `Retrying (${attempts})...` : 'Login'}
      </button>
      {state?.error && <p className="error">{state.error}</p>}
      {attempts >= 3 && <p className="error">Failed after 3 attempts. Check your connection.</p>}
    </form>
  );
}
```

<Callout type="warning" title="Do not auto-retry everything">
Only retry on network errors or timeouts. Do not retry on 400 Bad Request or 401 Unauthorized. Those will fail the same way every time.
</Callout>

## 7. Migration checklist: from useState to useActionState

| Pattern | React 18 | React 19 |
Form state	useState for every field	Native form inputs with name
Submission	onSubmit + e.preventDefault()	action attribute
Pending state	useState + manual toggle	isPending from useActionState
Error display	useState + manual clearing	state.error from useActionState
Success redirect	useEffect + router.push	return redirect from Server Action
| Optimistic UI | Manual temp state + rollback | useOptimistic hook |

**Step-by-step migration:**
1. Remove useState for form fields. Add name attributes to inputs instead.
2. Replace onSubmit with action. The action receives FormData automatically.
3. Move validation to the action. Client-side validation is still good UX, but the action is the source of truth.
4. Delete isSubmitting useState. Use isPending from useActionState.
5. Delete error useState. Use state.error from useActionState.
6. Add useOptimistic for instant updates. Wrap any list or count that updates after form submission.
8. When to keep useState

useActionState is for form submissions. It is not a replacement for all useState.

**Keep useState for:**
- Non-form UI state (modals, tabs, toggles)
- Complex local calculations
- Third-party library integration
- State that never touches a server

**Delete useState for:**
- Form field values
- Submission status
- Error messages from server
- Success confirmations
<Callout type="tip" title="The 80/20 rule">
After migrating my forms, I deleted 60% of my useState hooks. The remaining 40% were for UI state that had nothing to do with server submission. Your numbers will be similar.
</Callout>
